# Papyrus

A static homepage for hosting notes generated by Papyrus.
[Click here to start reading](https://itsamir-hs.github.io/papyrus)

## Features

- Grid of all notes, grouped by category (automatic, from the course name)
- Live search with highlighted matches (note titles and category names)
- Sorting: class session number (default), newest first, or alphabetical; grouped by category (default) and optionally reversed
- "جدید" tag on notes for 24 hours after they are added, or until the note is opened
- Theme switcher (light, dark, forest, paperLike, neon)
- Fluid layout that adapts to any screen size
- Notes list is rebuilt automatically on every push (GitHub Actions)

## Structure

```
papyrus/
├── index.html            # Homepage
├── styles.css            # Themes + styles
├── app.js                # Search, sorting, theme switcher, note rendering
├── notes.json            # Manifest (auto-generated)
├── update-manifest.js    # Regenerates notes.json
├── papyruswebicon.jpg    # Favicon + share-link image
├── .github/workflows/deploy.yml
├── note_<name>/          # A note
│   ├── note.html
│   └── note.md           # optional, source of the title (old layout note_<name>/output/index.html also works)
└── cat_<category>/       # Optional manual category folder
    └── note_<name>/
        └── note.html
```

## Adding a new note

1. Drop the note folder (containing `note.html`, or `output/index.html` in the old layout) in the repo root.
2. Commit and push. The workflow regenerates `notes.json` and deploys the site.

Without the workflow you can run `node update-manifest.js` yourself and commit `notes.json`.

## Title format

Titles follow `<course name> - <subject> - <class session>` (separator is a hyphen with spaces around it), for example:

```
ایمونولوژی - تاریخچهٔ ایمنی‌شناسی و ارتباط آن با آزمایشگاه - جلسه اول
```

- **Course name** (first part) becomes the category automatically.
- **Class session** (last part) is turned into a number for "sort by session". Words (اول, دوم, ... بیست و یکم) and digits (Persian or Latin) both work.
- A title that doesn't follow the format still shows up, just without a category / session number. The manifest script prints a warning for such notes.

Where the title itself comes from, first hit wins:

1. The `**مبحث:** <title>` line of `note.md` inside the note folder (the old `data/input/note.md` location, or any single `.md` file in the folder, also works)
2. A `<strong>مبحث:</strong> <title>` line inside the note file
3. The `<title>` of the note file
4. The folder name

## Categories

1. A note inside a `cat_<categoryName>` folder uses that folder name (underscores become spaces).
2. Otherwise the course name from the title is used.
3. Otherwise the note appears under "بدون دسته‌بندی".

Course names are matched ignoring Arabic/Persian letter variants and half-spaces, so small spelling differences end up in the same category.

## Sorting and the "new" tag

- Each note's `added` date is the moment the manifest script first saw it. It is stored in `notes.json` and kept on every later run (matched by the note's folder name, so moving a note into a `cat_` folder keeps its date). Updating or re-generating a note never makes it new again.
- The workflow commits `notes.json` back to the repo after each build; that is what remembers the dates. If you also run the script locally, pull before you push and don't commit your local `notes.json`.
- The first run with this system treats every existing note as already known, so nothing is tagged new at that point.
- A note shows the tag for 24 hours (`newNoteHours` in `app.js`), and it disappears earlier once the note is opened on that device.
- Pick one sort: **newest**, **session** (by session number only: every session 1, then every session 2 ..., whatever the course or category) or **alphabetical**. Two switches combine with any of them:
  - **دسته‌بندی** groups the notes into one section per category (alphabetical, "بدون دسته‌بندی" last), and the chosen sort orders the notes inside each section. So "category + session" lists each category's notes by session number.
  - **معکوس** reverses the order ("جدیدترین" turns into "قدیمی‌ترین"). Notes without a session number stay at the end; with grouping on, the category order is flipped too.
- Without grouping, the list is flat, so the latest notes of different categories sit side by side.
- The sorting choice is remembered in the browser.

## Deployment

`.github/workflows/deploy.yml` runs `node update-manifest.js` and publishes the site with GitHub Pages on every push to `main`.
One-time setup: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
